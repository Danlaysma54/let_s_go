# Правила backend

Дополняют корневой `AGENTS.md` для Kotlin/Spring Boot-кода.

## Структура модуля

Доменные модули: `identity`, `organization`, `venue`, `resource`, `availability`, `booking`, `payment`, `settlement`, `cancellation`, `notification`, `moderation`, `administration`, `audit`.

Каждый модуль развивается по правилам Spring Modulith:

```text
<module>/
  *Facade.kt        публичный синхронный контракт модуля
  *Command.kt       публичные команды и результаты
  *Event.kt         публичные доменные события
  internal/
    api/            HTTP-контроллеры и transport DTO
    application/    use cases и orchestration
    domain/         агрегаты, value objects и доменные сервисы
    infrastructure/ JPA, outbox и внешние адаптеры
```

По умолчанию Spring Modulith считает корневой пакет публичным, а вложенные пакеты — внутренними. Дополнительный публичный пакет разрешён только через `@NamedInterface`. Для реализованного модуля задавайте `@ApplicationModule(allowedDependencies = [...])`; архитектурный тест обязан оставаться зелёным. Создавайте только нужные слои, пустая формальная структура не требуется.

## Зависимости

- Внутри модуля зависимость направлена `api -> application -> domain`; `infrastructure` реализует порты внутренних слоёв.
- Модуль импортирует только корневой публичный контракт или явно объявленный `@NamedInterface` другого модуля.
- Общий пакет `shared` содержит только действительно сквозные примитивы, а не удобную свалку.
- JPA-сущность не покидает инфраструктурный слой и не используется как HTTP DTO.

## Инварианты

- Операции создания брони и обработки платежа идемпотентны.
- Защита от двойной брони обеспечивается ограничением базы и транзакцией, а не только предварительной проверкой.
- Пересекающиеся временные интервалы одной атомарной бронируемой секции взаимоисключающие, даже если представлены разными слотами.
- Деньги — `Long` в минимальных единицах и код валюты; для коэффициентов допустим `BigDecimal` с явным округлением.
- Моменты времени — `Instant`, локальные правила расписания — `LocalDate`/`LocalTime` вместе с `ZoneId` площадки.
- Любой входящий webhook сначала проверяется, затем дедуплицируется, после чего изменяет состояние.

## База и миграции

- Только Flyway, файл `V<version>__<description>.sql`.
- Расширения PostgreSQL устанавливает привилегированный provisioning-шаг; Flyway не пытается создавать их runtime-пользователем.
- В production миграции запускаются отдельной job под migration-role, а API стартует с `FLYWAY_ENABLED=false` под непривилегированным runtime-role.
- Уже применённую миграцию не изменять; создавать следующую.
- Изменения схемы проектировать совместимыми минимум с предыдущей версией приложения.
- Запросы геопоиска проверять через `EXPLAIN ANALYZE` на реалистичном объёме данных.

## Тесты

- Domain — быстрые unit-тесты без Spring.
- Application — тесты use case с подменой портов.
- Persistence и конкурентность — интеграционные тесты с настоящим PostgreSQL/PostGIS.
- HTTP — contract/component тесты против OpenAPI.
- Перед передачей: `./gradlew check`.
