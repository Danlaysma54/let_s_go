# Правила Flutter E2E

- Тест работает только через публичный интерфейс приложения и реальный HTTP API
  E2E-окружения.
- Каждый тест создаёт уникальные данные и может выполняться независимо.
- Для подготовки данных допустимы специальные test-support endpoints только в
  E2E-профиле backend.
- Не использовать произвольные задержки. Ожидать наблюдаемое состояние с
  ограниченным таймаутом.
- Исключать внешние платёжные и SMS-системы: их sandbox/stub поведение должно
  быть детерминированным.
- Скриншоты и логи при падении сохранять в корневой `artifacts/`.
- Селекторы должны опираться на стабильные `Key`, семантику или текст контракта,
  а не на координаты.
