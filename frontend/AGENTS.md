# Правила Flutter-клиента

## Структура

```text
lib/
  app/       корневой widget, маршрутизация, общие providers
  core/      HTTP, конфигурация, дизайн-система, общие технические примитивы
  features/  пользовательские возможности вертикальными срезами
```

Внутри feature при необходимости используются `data/`, `domain/`, `application/`, `presentation/`. Не создавайте пустые слои заранее.

## Состояние и навигация

- Riverpod — состояние и внедрение зависимостей.
- GoRouter — единый граф навигации и deep links.
- Dio — HTTP; transport DTO не должны использоваться напрямую в UI.
- Состояния загрузки, пустого результата и ошибки проектируются явно.
- Нельзя считать локально отображённый слот гарантированно доступным: подтверждение выполняет backend.

## Конфигурация и безопасность

- Адреса и публичные идентификаторы приходят через `--dart-define` или конфигурацию окружения.
- Секреты и приватные ключи в приложение не встраиваются.
- Токены хранятся только в защищённом хранилище после подключения авторизации.
- Клиент обращается к S3/CDN только по выданному backend URL и не получает постоянные storage credentials.

## Проверки

- Форматирование: `dart format --output=none --set-exit-if-changed lib test integration_test`.
- Анализ: `flutter analyze`.
- Тесты: `flutter test`.
- Критический пользовательский сценарий: integration test на реальном backend E2E-окружения.
