# 0001. Модульный монолит для backend

- Статус: accepted
- Дата: 2026-10-07
- Владельцы: команда разработки

## Контекст

Проект запускается с небольшой командой, но содержит домены каталога, доступности, бронирования, оплаты и управления площадкой. Между ними нужны строгие транзакции, особенно при удержании слота и подтверждении платежа.

## Решение

Backend реализуется как один развёртываемый Spring Boot-процесс с явными доменными модулями. Каждый модуль владеет своими таблицами и публикует наружу только application-интерфейсы и события. Фоновые обработчики используют тот же код и могут быть вынесены в отдельный процесс без разделения репозитория.

## Рассмотренные варианты

- Микросервисы отклонены на старте из-за операционной стоимости, распределённых транзакций и преждевременного разделения команды.
- Неструктурированный монолит отклонён, потому что быстро создаёт неявные зависимости и общую модель данных.

## Последствия

Поставка и локальная разработка остаются простыми. Границы модулей необходимо проверять тестами архитектуры. Вынос модуля в сервис допустим только при измеренной потребности в независимом масштабировании или жизненном цикле.
