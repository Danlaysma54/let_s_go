# Правила разработки

Эти правила действуют во всём репозитории. Файл `AGENTS.md` в дочернем каталоге может уточнять их, но не отменяет требования по безопасности, контрактам и проверкам.

## Перед началом работы

1. Прочитайте этот файл и ближайший к изменяемому коду `AGENTS.md`.
2. Найдите связанную спецификацию в `docs/specs/`, архитектуру в `docs/architecture/` или системный документ в `docs/system/`.
3. Если меняется внешний API, сначала обновите `docs/api/src/openapi.yaml`.
4. Не принимайте неоднозначные продуктовые решения без фиксации допущения или уточнения у владельца продукта.

## Границы проекта

- `backend/` — единый модульный монолит. Модули общаются через публичные application-интерфейсы и доменные события, а не через чужие таблицы или внутренние классы.
- `frontend/` — Flutter-клиент. Бизнес-сценарии группируются по feature, общая инфраструктура хранится в `core/`.
- `web/` — React-клиент для B2B и административных сценариев.
- `docs/api/src/openapi.yaml` — источник истины для публичного HTTP API.
- Денежные значения передаются целым количеством минимальных единиц валюты. `float` и `double` для денег запрещены.
- Время хранится в UTC; локальная зона площадки хранится отдельным IANA-идентификатором.

## Обязательный цикл изменения

1. Определить затронутый контракт и инварианты.
2. Внести минимальное связное изменение.
3. Добавить или обновить тесты.
4. Запустить проверки ближайшего компонента, затем общие проверки.
5. Обновить документацию, если поведение, контракт или архитектурное решение изменились.

## Запрещено

- Коммитить секреты, `.env`, ключи подписи, токены и реальные персональные данные.
- Редактировать сгенерированные файлы вместо их источника.
- Обходить модульные границы прямыми зависимостями на внутреннюю реализацию.
- Добавлять миграцию, которая зависит от ручного изменения базы.
- Ослаблять линтеры или удалять тест ради прохождения CI без описанной причины.

## Проверки

- Backend: `cd backend && ./gradlew check`
- Flutter: `cd frontend && flutter analyze && flutter test`
- Web: `cd web && npm ci && npm run lint && npm run build`
- Инфраструктура: `docker compose config` и `docker compose -f compose.e2e.yml config`
- Полный набор: `mise run check && mise run test`

## Документация решений

- Поведение функции: `docs/specs/<feature>.md`.
- Реализация функции: `docs/architecture/<feature>.md`.
- Сквозное необратимое решение: ADR в `docs/adr/`.
- Инструкция эксплуатации: `docs/operations/`.
- Временный план реализации: `docs/plans/`; после завершения переместить в `docs/archive/`.
